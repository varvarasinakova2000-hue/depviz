# depviz — визуализатор графа зависимостей пакетов Python

Практическая работа № 2 по дисциплине «Конфигурационное управление»,
вариант 25.

## Общее описание

`depviz` — CLI-инструмент для построения и визуализации графа
зависимостей пакетов Python (pip). Готовые менеджеры пакетов и библиотеки
для получения зависимостей не используются: данные загружаются
напрямую из репозитория пакетов средствами стандартной библиотеки.

Текущее состояние — **этап 3: основные операции**. Приложение строит
граф зависимостей пакета с учётом транзитивности алгоритмом обхода
в глубину (DFS) без рекурсии, ограничивает анализ максимальной глубиной,
находит циклические зависимости и поддерживает режим тестового
репозитория, в котором граф пакетов задаётся текстовым файлом.

Требования: Python 3.8+ (используется только стандартная библиотека),
доступ в интернет для работы с репозиторием PyPI (режим `remote`).

## Параметры командной строки

| Параметр | Обязательный | По умолчанию | Описание |
|---|---|---|---|
| `-p`, `--package` | да | — | имя анализируемого пакета |
| `-r`, `--repo` | да | — | URL репозитория или путь к файлу тестового репозитория |
| `-m`, `--mode` | нет | `remote` | режим работы: `remote` или `test` |
| `-v`, `--version` | в режиме `remote` | — | версия пакета или `latest` |
| `-o`, `--output` | нет | `graph.svg` | имя файла с изображением графа |
| `-d`, `--max-depth` | нет | `3` | максимальная глубина анализа зависимостей |
| `-h`, `--help` | нет | — | справка по параметрам |

### Проверка параметров

- **package** — не пустое; в режиме `remote` — имя по правилам PyPI
  (латинские буквы, цифры, а также `.`, `_`, `-` внутри имени);
  в режиме `test` — только большие латинские буквы (`A`, `B`, `AB`).
- **repo** — в режиме `remote` — URL со схемой `http` или `https`,
  с адресом сервера и без пробелов; в режиме `test` — существующий
  файл в кодировке UTF-8 (не каталог).
- **mode** — только `remote` или `test`.
- **version** — номер версии в формате PEP 440 (`1.0`, `2.31.0`,
  `3.0.0rc1`, `1.2.post1`, `1.0.dev3`) или слово `latest` — последняя
  версия. В режиме `remote` версию нужно указать обязательно;
  в режиме `test` у пакетов нет версий, и параметр можно не задавать.
- **output** — не пустое имя файла с расширением `.svg`,
  без символов `< > : " / \ | ? *`; каталог файла должен существовать;
  путь не должен указывать на существующий каталог.
- **max-depth** — целое число от 1 до 100.

Отсутствие обязательных параметров и неизвестные опции обрабатывает
`argparse` (вывод подсказки `usage` и код возврата `2`).

### Режимы работы

- `remote` — данные о пакетах берутся из репозитория PyPI по URL
  (например, `https://pypi.org/pypi`).
- `test` — вместо реального репозитория используется файл описания
  графа, в котором пакеты называются большими латинскими буквами.

## Построение графа зависимостей

### Алгоритм: DFS без рекурсии

Граф строится функцией `build_graph` (модуль `graph.py`) обходом
в глубину с явным стеком вместо рекурсии:

1. В стек кладётся корневой пакет с глубиной 0.
2. Из стека извлекается пакет. Если он уже обработан на той же или
   меньшей глубине, он пропускается.
3. Если глубина пакета меньше максимальной, загружаются его прямые
   зависимости, и они кладутся в стек с глубиной на 1 больше
   (в обратном порядке, чтобы первая зависимость обрабатывалась первой).
4. Шаги 2–3 повторяются, пока стек не опустеет.

Зависимости каждого пакета загружаются из источника не более одного
раза. Рекурсия не используется ни при построении графа, ни при поиске
циклов, поэтому длинные цепочки зависимостей не вызывают переполнения
стека вызовов.

### Максимальная глубина

Корневой пакет имеет глубину 0, его прямые зависимости — 1 и т. д.
Зависимости анализируются только у пакетов с глубиной меньше
`--max-depth`: при `-d 1` выводятся только прямые зависимости.
Пакеты на максимальной глубине входят в граф, но их зависимости
не загружаются — в выводе для них указано
`... (достигнута максимальная глубина)`.

Если пакет сначала найден по длинному пути (и оказался на границе
глубины), а затем по более короткому, он раскрывается заново
с меньшей глубиной, поэтому результат не зависит от порядка обхода.

### Циклические зависимости

Пакет, который уже обработан, повторно в стек не раскрывается
(кроме случая более короткого пути, описанного выше), поэтому циклы
вида `A -> B -> C -> A` не приводят к бесконечному обходу. После
построения графа функция `find_cycles` ещё одним обходом в глубину
без рекурсии ищет циклы: цикл фиксируется, когда обход встречает
пакет, который уже находится на текущем пути от корня. Для каждой
такой «замыкающей» зависимости выводится один цикл. Циклы за пределами
максимальной глубины не учитываются, так как эти зависимости
не анализировались.

### Источник данных: репозиторий PyPI

- для корневого пакета используется версия из `--version`, для
  транзитивных зависимостей — последняя версия пакета в репозитории;
- учитываются только обязательные зависимости; необязательные
  (extras, например `requests[socks]`) в граф не входят;
- зависимости с условиями окружения (например,
  `python_version < '3.10'`) входят в граф независимо от условия;
- имена пакетов приводятся к нормальной форме PEP 503
  (`Jinja2` → `jinja2`, `charset_normalizer` → `charset-normalizer`),
  чтобы один пакет не попадал в граф дважды под разными именами.

Метаданные загружаются через JSON API репозитория
(`<URL>/<пакет>/<версия>/json` или `<URL>/<пакет>/json`), из ответа
берётся поле `info.requires_dist` в формате PEP 508.

## Тестовый репозиторий

### Формат файла

По одной строке на пакет: слева от двоеточия — имя пакета, справа —
его прямые зависимости через пробел. Имена пакетов — большие латинские
буквы. Пустые строки и текст после `#` игнорируются. Пакет, который
упомянут только как зависимость, считается пакетом без зависимостей.

```
# комментарий
A: B C
B: D
C: D
D:
```

Ошибки в файле (нет двоеточия, недопустимое имя, повторное описание
пакета, повторная зависимость) выводятся с номером строки.

### Примеры тестовых репозиториев (`tests/repos/`)

| Файл | Что демонстрирует |
|---|---|
| `simple.txt` | общая зависимость («ромб»): `B` и `C` зависят от `D` |
| `chain.txt` | цепочка `A -> B -> ... -> F` для проверки максимальной глубины |
| `cycle.txt` | цикл `A -> B -> C -> A` |
| `self_cycle.txt` | пакет зависит сам от себя |
| `complex.txt` | несколько циклов, общие зависимости, неописанный пакет `I` |
| `broken.txt` | ошибка формата (строка без двоеточия) |

## Ошибки и коды возврата

Ошибки при получении данных выводятся в stderr с кодом возврата `1`:

- заданной версии нет в репозитории, хотя сам пакет есть (HTTP 404);
- пакета нет в репозитории или URL указывает не на JSON API —
  с подсказкой проверить имя пакета и URL;
- репозиторий вернул другую ошибку HTTP;
- не удалось подключиться к репозиторию или истекло время ожидания
  ответа (5 секунд) — при сбое сети запрос повторяется, всего
  до 3 попыток;
- ответ не является JSON-документом или не содержит раздела `info`;
- строка зависимости не соответствует формату PEP 508;
- ошибка формата файла тестового репозитория или корневого пакета
  нет в тестовом репозитории.

| Код | Значение |
|---|---|
| `0` | граф успешно построен |
| `1` | ошибка при получении данных из репозитория |
| `2` | ошибка в параметрах командной строки |

## Описание функций

### src/graph.py — граф зависимостей

| Функция / класс | Назначение |
|---|---|
| `DependencyGraph` | граф: корень, зависимости проанализированных пакетов (`edges`) и глубины пакетов (`depths`) |
| `DependencyGraph.nodes` | пакеты графа в порядке обнаружения |
| `DependencyGraph.is_expanded(node)` | анализировались ли зависимости пакета |
| `DependencyGraph.edge_count()` | число зависимостей (рёбер) в графе |
| `build_graph(root, get_dependencies, max_depth)` | строит граф обходом в глубину без рекурсии |
| `find_cycles(graph)` | находит циклические зависимости обходом в глубину без рекурсии |

### src/sources.py — источники зависимостей

| Функция | Назначение |
|---|---|
| `make_local_source(path, package)` | источник из файла тестового репозитория |
| `remote_dependencies(repository, root, version, package)` | загружает обязательные зависимости пакета из PyPI |
| `make_remote_source(repository, package, version)` | источник из репозитория PyPI |
| `make_source(config)` | выбирает источник по режиму работы |

Источник — пара (корневой пакет, функция, возвращающая прямые
зависимости пакета).

### src/local_repo.py — тестовый репозиторий

| Функция | Назначение |
|---|---|

| `parse_local_repository(text)` | разбирает описание графа в словарь пакетов |
| `load_local_repository(path)` | читает и разбирает файл тестового репозитория |

### src/config.py — параметры командной строки

| Функция / класс | Назначение |
|---|---|
| `ConfigError` | исключение: ошибка в значении параметра |
| `Config` | проверенные параметры запуска |

| `make_config(args)` | проверяет все разобранные аргументы и собирает `Config` |

### src/pypi.py — работа с репозиторием PyPI

| Функция / класс | Назначение |
|---|---|

### src/requirements.py — строки зависимостей

### src/errors.py и src/main.py

| Функция / класс | Назначение |
|---|---|
| `RepositoryError` | исключение: ошибка получения данных из репозитория |

## Сборка и запуск тестов

Сборка не требуется. Запуск приложения:

```bash
./run.sh -p requests -r https://pypi.org/pypi -v 2.31.0
./run.sh -p A -r tests/repos/complex.txt -m test -d 10
```

```bat
run.bat -p requests -r https://pypi.org/pypi -v 2.31.0
run.bat -p A -r tests\repos\complex.txt -m test -d 10
```

Запуск модульных тестов из корня репозитория (доступ к сети не нужен,
ответы репозитория подменяются с помощью `unittest.mock`):

```bash
python -m unittest -v
```

Демонстрационные скрипты (Linux / Windows):

```bash
./scripts/test_params.sh
./scripts/test_repos.sh
./scripts/test_errors.sh
```

```bat
scripts\test_params.bat
scripts\test_repos.bat
scripts\test_errors.bat
```
