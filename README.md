# depviz — визуализатор графа зависимостей пакетов Python

Практическая работа № 2 по дисциплине «Конфигурационное управление»,
вариант 25.

## Общее описание

`depviz` — CLI-инструмент для построения и визуализации графа
зависимостей пакетов Python (pip). Готовые менеджеры пакетов и библиотеки
для получения зависимостей не используются: данные загружаются
напрямую из репозитория пакетов средствами стандартной библиотеки.

Текущее состояние — **этап 2: сбор данных**. Приложение проверяет
параметры командной строки, загружает метаданные заданной версии пакета
из репозитория по URL и выводит все его прямые зависимости.

Требования: Python 3.8+ (используется только стандартная библиотека),
доступ в интернет для работы с репозиторием PyPI.

## Структура репозитория

```
src/
  main.py               точка входа: параметры, загрузка, вывод
  config.py             описание и проверка параметров командной строки
  pypi.py               загрузка метаданных пакета из JSON API PyPI
  requirements.py       разбор строк зависимостей (PEP 508)
tests/
  __init__.py           подключение каталога src для тестов
  test_config.py        тесты параметров командной строки
  test_pypi.py          тесты загрузки данных (сеть подменяется)
  test_requirements.py  тесты разбора строк зависимостей
  repos/simple.txt      файл тестового репозитория для режима test
scripts/
  test_params.*         демонстрация получения зависимостей пакетов
  test_errors.*         демонстрация обработки ошибок
run.sh, run.bat         скрипты запуска приложения
```

## Параметры командной строки

| Параметр | Обязательный | По умолчанию | Описание |
|---|---|---|---|
| `-p`, `--package` | да | — | имя анализируемого пакета |
| `-r`, `--repo` | да | — | URL репозитория или путь к файлу тестового репозитория |
| `-m`, `--mode` | нет | `remote` | режим работы: `remote` или `test` |
| `-v`, `--version` | в режиме `remote` | — | версия пакета или `latest` |
| `-o`, `--output` | нет | `graph.svg` | имя файла с изображением графа |
| `-d`, `--max-depth` | нет | `3` | максимальная глубина анализа зависимостей |
| `-h`, `--help` | нет | — | справка по параметрам |

### Проверка параметров

- **package** — не пустое; в режиме `remote` — имя по правилам PyPI
  (латинские буквы, цифры, а также `.`, `_`, `-` внутри имени);
  в режиме `test` — только большие латинские буквы (`A`, `B`, `AB`).
- **repo** — в режиме `remote` — URL со схемой `http` или `https`,
  с адресом сервера и без пробелов; в режиме `test` — существующий
  файл в кодировке UTF-8 (не каталог).
- **mode** — только `remote` или `test`.
- **version** — номер версии в формате PEP 440 (`1.0`, `2.31.0`,
  `3.0.0rc1`, `1.2.post1`, `1.0.dev3`) или слово `latest` — последняя
  версия. В режиме `remote` версию нужно указать обязательно;
  в режиме `test` у пакетов нет версий, и параметр можно не задавать.
- **output** — не пустое имя файла с расширением `.svg`,
  без символов `< > : " / \ | ? *`; каталог файла должен существовать;
  путь не должен указывать на существующий каталог.
- **max-depth** — целое число от 1 до 100.

Отсутствие обязательных параметров и неизвестные опции обрабатывает
`argparse` (вывод подсказки `usage` и код возврата `2`).

### Режимы работы

- `remote` — данные о пакетах берутся из репозитория по URL
  (например, `https://pypi.org/pypi`).
- `test` — вместо реального репозитория используется файл описания
  графа, в котором пакеты обозначаются большими латинскими буквами
  (пример — `tests/repos/simple.txt`). Получение зависимостей в этом
  режиме будет реализовано на этапе 3, сейчас программа сообщает,
  что режим пока не поддерживается.

## Получение прямых зависимостей

Используется формат пакетов Python (pip) и JSON API репозитория PyPI:

- `<URL>/<пакет>/<версия>/json` — метаданные заданной версии;
- `<URL>/<пакет>/json` — метаданные последней версии (`--version latest`).

Запрос выполняется модулем `urllib.request`. Из ответа берётся
поле `info.requires_dist` — список строк зависимостей в формате
PEP 508, например `idna<4,>=2.5` или
`PySocks (!=1.5.7,>=1.5.6) ; extra == 'socks'`. Каждая строка
разбирается модулем `requirements.py` на имя пакета, ограничение
версии и условие (маркер окружения).

Выводятся все прямые зависимости пакета в два списка:

- **обязательные** — устанавливаются всегда; если у зависимости есть
  условие (например, `python_version < '3.10'`), оно показывается
  в квадратных скобках;
- **необязательные (extras)** — нужны только при установке пакета
  с дополнительной функциональностью, например `requests[socks]`.

Если у пакета нет зависимостей (`requires_dist` пусто), выводится `(нет)`.

### Ошибки при работе с репозиторием

Сообщение выводится в stderr, код возврата `1`:

- заданной версии нет в репозитории, хотя сам пакет есть (HTTP 404);
- пакета нет в репозитории или URL указывает не на JSON API
  (HTTP 404 и для версии, и для пакета) — с подсказкой проверить
  имя пакета и URL;
- репозиторий вернул другую ошибку HTTP;
- не удалось подключиться к репозиторию или истекло время ожидания
  ответа (5 секунд) — при сбое сети запрос повторяется, всего
  до 3 попыток;
- ответ не является JSON-документом или не содержит раздела `info`;
- строка зависимости не соответствует формату PEP 508.

### Коды возврата

| Код | Значение |
|---|---|
| `0` | зависимости успешно получены |
| `1` | ошибка при получении данных из репозитория |
| `2` | ошибка в параметрах командной строки |

## Описание функций

### src/config.py — параметры командной строки

| Функция / класс | Назначение |
|---|---|
| `ConfigError` | исключение: ошибка в значении параметра |
| `Config` | проверенные параметры запуска |
| `build_parser()` | создаёт парсер `argparse` со всеми параметрами |
| `validate_mode(mode)` | проверяет режим работы |
| `validate_package(name, mode)` | проверяет имя пакета с учётом режима |
| `validate_url(url)` | проверяет URL репозитория |
| `validate_test_repo(path)` | проверяет, что файл тестового репозитория существует и читается в UTF-8 |
| `validate_repository(repository, mode)` | выбирает проверку URL или файла в зависимости от режима |
| `validate_version(version, mode)` | проверяет версию пакета, в режиме `remote` — её наличие |
| `validate_output(output)` | проверяет имя файла с изображением графа |
| `validate_max_depth(value)` | преобразует глубину анализа в число и проверяет диапазон |
| `make_config(args)` | проверяет все разобранные аргументы и собирает `Config` |

### src/pypi.py — работа с репозиторием

| Функция / класс | Назначение |
|---|---|
| `RepositoryError` | исключение: ошибка получения данных из репозитория |
| `PackageNotFoundError` | исключение: адрес вернул HTTP 404 |
| `NetworkError` | исключение: нет соединения или истекло время ожидания |
| `PackageInfo` | имя, версия и кортеж прямых зависимостей пакета |
| `build_url(repository, package, version)` | формирует URL метаданных пакета в JSON API |
| `request_once(url)` | выполняет один HTTP-запрос и возвращает тело ответа |
| `download(url)` | скачивает данные, повторяя запрос при сбое сети |
| `fetch_json(url)` | скачивает и разбирает JSON-документ |
| `parse_requirements(requires_dist)` | разбирает список строк `requires_dist` |
| `parse_package_info(data)` | извлекает имя, версию и зависимости из ответа |
| `package_exists(repository, package)` | проверяет, есть ли пакет в репозитории в любой версии |
| `not_found_message(repository, package, version)` | формирует сообщение: нет версии или нет пакета |
| `get_package_info(repository, package, version)` | получает прямые зависимости пакета заданной версии |

### src/requirements.py — строки зависимостей

| Функция / класс | Назначение |
|---|---|
| `RequirementError` | исключение: строка не соответствует формату PEP 508 |
| `Requirement` | зависимость: имя, ограничение версии, условие; свойства `extra` и `is_optional` |
| `normalize_name(name)` | приводит имя пакета к нормальной форме (PEP 503) |
| `parse_specifier(rest, text)` | выделяет ограничение версии, снимает скобки старого формата |
| `parse_requirement(text)` | разбирает строку зависимости в `Requirement` |

### src/main.py — точка входа

| Функция | Назначение |
|---|---|
| `load_package(config)` | получает сведения о пакете из источника, заданного в настройках |
| `print_requirements(requirements)` | выводит список зависимостей по одной на строке |
| `print_dependencies(info)` | выводит обязательные и необязательные прямые зависимости |
| `main(argv=None)` | точка входа: параметры, загрузка, вывод; возвращает код завершения |

## Сборка и запуск тестов

Сборка не требуется. Запуск приложения:

```bash
./run.sh -p requests -r https://pypi.org/pypi -v 2.31.0
```

```bat
run.bat -p requests -r https://pypi.org/pypi -v 2.31.0
```

Запуск модульных тестов из корня репозитория (доступ к сети не нужен,
ответы репозитория подменяются с помощью `unittest.mock`):

```bash
python -m unittest -v
```

Демонстрационные скрипты (Linux / Windows):

```bash
./scripts/test_params.sh
./scripts/test_errors.sh
```

```bat
scripts\test_params.bat
scripts\test_errors.bat
```
